## D-001. Имя Janus и репозиторий `janus-switcher`

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Программа выросла из идеи Punto Switcher, но не является его форком и не должна
носить чужое имя. Нужно короткое имя, которое объясняет суть и не конфликтует с торговыми марками.

**Решение.** Имя **Janus** (Янус, двуликий бог переходов): два лица — две раскладки.
Репозиторий — `petrovich811/janus-switcher`, модуль —
`github.com/petrovich811/janus-switcher`.

**Альтернативы.** Оставить `punto` (риск претензий и путаницы с оригиналом); нейтральное
`layout-switcher` (скучно и занято); `perevod` (не отражает переворот).

**Последствия.**
- Конфиг переносится из `~/.config/punto` в `~/.config/janus` (миграция в `internal/config`).
- dconf-пути — `janus-main`, `janus-alt`. Код создаёт только их; старые `punto-*` он не
  добавляет, но и не вычищает автоматически: если они остались в списке от прежней версии,
  их нужно убрать вручную (в этой системе убраны).
- В коде остались упоминания Punto только как аналога и в миграции.

## D-002. Go, без cgo, один бинарник

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Нужен маленький демон без root, который легко собрать и перенести на Linux и
Windows. GTK/Xlib/cgo тянут системные зависимости и усложняют кросс-компиляцию.

**Решение.** Чистый Go, `CGO_ENABLED=0`, один бинарник. X11 — через `github.com/jezek/xgb`,
D-Bus — через `github.com/godbus/dbus/v5`, Win32 — через `golang.org/x/sys/windows` и
`syscall`.

**Альтернативы.** C++/Qt (тяжело, cgo, лицензии); Rust + GTK (сложнее сборка); Python
(зависимости и запуск).

**Последствия.**
- Нет GTK-настроек: интерфейс — локальная веб-страница.
- Приходится вручную описывать Win32-структуры и X11-протокол; это цена отсутствия cgo.
- Сборка Windows — обычная кросс-компиляция из Linux.

## D-003. Горячие клавиши Linux через GNOME custom keybindings

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Wayland не даёт приложению глобально перехватывать клавиатуру. Нужен способ,
который работает и в Wayland, и в X11, без root и без низкоуровневого хука.

**Решение.** Демон прописывает пользовательские сочетания GNOME через `gsettings`
(`org.gnome.settings-daemon.plugins.media-keys.custom-keybinding`). Команда сочетания —
`janus action main` / `janus action alt`. Меняешь сочетание в веб-интерфейсе — демон
переписывает запись.

**Альтернативы.** Глобальный хук через `/dev/input` (нужны права, навязчиво); портал
GlobalShortcuts (не везде и нестабильно); XGrabKey (только X11).

**Последствия.**
- Автоматическое назначение работает только в GNOME. В KDE/XFCE/Sway пользователь назначает
  `janus action main` сам.
- Нужен запущенный `gsd-media-keys`; `janus diag` это проверяет.
- Сочетание без модификатора GNOME не берёт (кроме функциональных клавиш); это ограничение
  записано в README.

## D-004. Ввод на Linux через `/dev/uinput`

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Нужно отправлять Ctrl+C, Ctrl+V и переключение раскладки в **чужое** окно,
будь оно Wayland или X11. Синтетические события X11 не видны Wayland-приложениям.

**Решение.** Виртуальная клавиатура через `/dev/uinput`: события идут через ядро и выглядят
как настоящая клавиатура. Устройство создаётся лениво, при первом действии, чтобы не пугать
рабочий стол появлением клавиатуры на каждом запуске.

**Альтернативы.** XTest (только X11); `ydotool` (внешняя зависимость и демон); портал
RemoteDesktop (сложно и не везде).

**Последствия.**
- Нужен доступ к `/dev/uinput`; обычно он есть у активной сессии.
- Демон не требует root, но при отсутствии прав переворот не работает.
- `janus diag` показывает доступность uinput отдельной строкой.

## D-005. Буфер Linux через X11-протокол на чистом Go

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Нужно читать и писать CLIPBOARD без GTK и без внешних утилит. В GNOME на
Wayland буфер зеркалируется в X11 через Xwayland, поэтому X11-клиент может читать то, что
скопировало Wayland-приложение, и наоборот.

**Решение.** Собственный X11-клиент на `xgb`: `ConvertSelection`, `SelectionNotify`,
`PropertyNotify`, поддержка INCR, окно-приёмник. Запись — `SetSelectionOwner` + обслуживание
`SelectionRequest`.

**Альтернативы.** `xclip`/`wl-copy` (внешние зависимости, разное поведение); GTK (cgo);
libwayshot (не тот уровень).

**Последствия.**
- Работает только при наличии Xwayland; в чистом Sway буфера нет.
- Только plain text.
- Появилась проба `probe` для определения факта копирования и необходимость её восстановления
  (см. D-010, D-011).

## D-006. Переворот по физическим клавишам, а не транслитерация

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Можно переводить текст по таблице «буква → буква» (а → f, б → ,), а можно — по
физическим клавишам: какая клавиша нажата в одной раскладке и что она даёт в другой.

**Решение.** Хранить таблицы `клавиша → символ` для US и RU, переводить через физическую
клавишу. Это ровно то, что произошло бы, если бы пользователь перепечатал текст в другой
раскладке.

**Альтернативы.** Транслитерация по буквам (неверно для punctuation и цифр); словарь (тяжело,
не нужно для одного слова).

**Последствия.**
- Пунктуация тоже едет по клавише: `привет, мир` → `ghbdtn? vbh`.
- Круговой переворот обратим для символов, которые есть в обеих таблицах.
- Нельзя «улучшать» пунктуацию, не пересмотрев продуктовое поведение и тесты.

## D-007. Настройки — локальная веб-страница, значок — SNI

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Нужны настройки без GTK/Qt и без терминала. Пользователь должен назначить
сочетание нажатием, а не вводом строки.

**Решение.** Встроенная HTML-страница на `127.0.0.1:8791`, JSON API и значок
StatusNotifierItem в трее (Linux) / `Shell_NotifyIcon` (Windows). Изменяющие запросы требуют
заголовок `X-Janus: 1`.

**Альтернативы.** GTK-окно (cgo/зависимости); терминальный мастер (неудобно); внешний
Electron (огромный).

**Последствия.**
- Страница открывается в браузере; отдельного окна нет.
- Заголовок `X-Janus` — единственная защита от случайного вызова со сторонней страницы;
  убирать его нельзя.
- UI и сообщения — по-русски.

## D-008. Windows через Win32, кросс-компиляция, alpha

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** У автора нет живой Windows. Нужно было решить: не делать Windows вовсе,
делать и не выпускать до теста, или выпустить как alpha с диагностикой.

**Решение.** Реализовать Windows на Win32 (`RegisterHotKey`, `SendInput`, clipboard,
`Shell_NotifyIcon`, HKL), собирать кросс-компиляцией, выпускать как **alpha** с командой
`janus diag`. Не выдавать сборку за проверенную систему.

**Альтернативы.** Не поддерживать Windows; ждать живую машину; эмулятор (Wine не заменяет
Win32-поведение).

**Последствия.**
- README и релизы явно помечают Windows как alpha.
- `janus diag` — основной инструмент сбора проблем.
- Любые утверждения о Windows в документации должны быть помечены как непроверенные, если
  нет живого прогона.

## D-009. Не делать автопереворот по мере набора

**Дата:** 2026-11-21. **Статус:** принято.

**Контекст.** Punto Switcher умеет следить за набором и переворачивать слово по пробелу.
Это требует чтения `/dev/input` (права, конфликты с другими переключателями) и эвристик языка.

**Решение.** Только переворот по явной горячей клавише. Автопереворот — не цель проекта.

**Альтернативы.** Следить за `/dev/input`; читать буфер по таймеру (медленно и навязчиво).

**Последствия.**
- Меньше прав и меньше побочных эффектов.
- Пользователь должен нажать клавишу; это осознанный компромисс.

## D-010. Отложенное восстановление буфера под `e.run`

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** После вставки нужно вернуть прежний буфер, но приложению нужно время прочитать
новый текст. Изначально восстановление было отдельной горутиной с `Sleep(700ms)`; она могла
затереть результат нового переворота или то, что пользователь скопировал сам.

**Решение.** `restoreTask` с таймером живёт под `e.run`. Новый `Run` сначала сбрасывает
отложенное восстановление; таймер проверяет, что в буфере всё ещё **наш** результат, и только
тогда пишет прежний текст. `Engine.Close` сбрасывает восстановление до остановки платформы.

**Альтернативы.** Синхронный `Sleep` в `Run` (блокирует демон); восстановление без проверки
(затирает чужой текст); не восстанавливать вовсе (плохой UX).

**Последствия.**
- Гонка с новым переворотом устранена.
- Остаётся неустранимая неатомарность: между `ReadText` и `WriteText` другая программа может
  записать своё. Это записано в README.
- 700 мс — эвристика; медленное приложение может прочитать старый текст.

## D-011. Linux-проба буфера и чередующиеся X11-свойства

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** На Linux нельзя узнать, скопировало ли приложение выделение, не положив в буфер
маркер. После неудачного переворота маркер оставался у пользователя. Кроме того, при таймауте
запоздавший `SelectionNotify` мог быть принят за ответ на следующий запрос.

**Решение.**
- `BeginCopy` кладёт `janus-clipboard-probe-…`; `WaitCopied` ждёт, пока буфер перестанет быть
  пробой.
- При неудаче движок вызывает `RestoreAfterFailedCopy(before)`, и проба заменяется прежним
  текстом.
- Для запросов используются четыре чередующихся свойства (`JANUS_SELECTION_A..D`), чтобы
  запоздавший ответ не будил следующий запрос. `reqMu` сериализует чтения.

**Альтернативы.** XFixes `SelectSelectionInput` (сложнее, ещё один протокол); не использовать
пробу (не отличить копирование от старого буфера); оставить один атом (поздние ответы
смешиваются).

**Последствия.**
- Пользовательский буфер не остаётся с пробой.
- Отказ владельца (`Property=0`) больше не вешает чтение на 1,5 с.
- Остаётся редкий случай: запоздавший **отказ** может быть приписан текущему запросу;
  принято как допустимый риск alpha.

## D-012. Windows: `Preflight` до IPC

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** `ipc.Listen` на Windows пишет порт и токен в `~/.config/janus/ipc.port`.
Второй экземпляр демона успевал перезаписать файл, затем падал на проверке единственного
экземпляра и завершался, оставляя работающий демон без IPC.

**Решение.** `windowsPlatform.Preflight()` захватывает mutex `Local\janus-switcher` **до**
`ipc.Listen` и HTTP. `runDaemon` вызывает его первым; второй экземпляр выходит, не трогая
`ipc.port`.

**Альтернативы.** Проверять порт из `ipc.port` и подключаться (сложнее, гонка); именованный
pipe (больше Win32-кода); не делать проверку (зомби-демон).

**Последствия.**
- Второй экземпляр завершается до записи файла.
- Mutex удерживается на процесс; `CloseHandle` при остановке.
- Порядок `Preflight → IPC → HTTP → Start` нельзя переставлять без пересмотра.

## D-013. Windows: окно-владелец буфера на отдельном потоке

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** `OpenClipboard` с `NULL` плохо сочетается с `EmptyClipboard` +
`SetClipboardData`. Нужно окно-владелец. Если создать его на произвольном потоке Go, поток
может быть переиспользован/завершён, окно исчезнет, и буфер сломается.

**Решение.** Отдельная горутина с `runtime.LockOSThread`, регистрацией класса, созданием
скрытого message-only окна и циклом `GetMessage/Translate/Dispatch`. `ReadText`/`WriteText`
дополнительно закрепляют поток на время `OpenClipboard…CloseClipboard`.

**Альтернативы.** `OpenClipboard(0)` (ненадёжно с `EmptyClipboard`); окно из `winhost`
(связывание пакетов, нужен HWND до `Start`); окно на каждый вызов (дорого и рискованно).

**Последствия.**
- Окно живёт столько же, сколько процесс.
- Появился небольшой Win32-цикл сообщений в пакете clipboard.
- На живой Windows не проверялось; при проблемах смотреть `janus diag` и лог.

## D-014. Атомарный конфиг и изоляция `JANUS_CONFIG_DIR`

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** `os.WriteFile` мог оставить обрезанный JSON при сбое. `Update` менял память до
записи, и при ошибке диск и работающие настройки расходились. Тесты с `JANUS_CONFIG_DIR`
подмешивали реальный `~/.config/punto`.

**Решение.**
- `saveLocked`: `CreateTemp` в каталоге конфига, запись, `Chmod(0644)`, `Rename`.
- `Update`: снимок старого конфига; при ошибке записи — откат памяти.
- `migrateLegacy` не выполняется, если задан `JANUS_CONFIG_DIR`.

**Альтернативы.** Прямая запись (риск обрезанного файла); WAL/БД (избыточно); игнорировать
ошибку записи (плохо).

**Последствия.**
- Атомарная видимость файла на Linux; на Windows `Rename` заменяет файл, но гарантии
  crash-durability нет (нет `fsync` каталога).
- Ошибка сохранения API возвращает 500 и не меняет работающие настройки.
- Тесты и эксперименты изолированы.

## D-015. `ptr()` вместо голого `uintptr → unsafe.Pointer`

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** `GlobalLock` возвращает `uintptr`; `unsafe.Slice((*uint16)(unsafe.Pointer(p)), n)`
вызывает предупреждение `go vet` `possible misuse of unsafe.Pointer`. Память при этом вне
Go-кучи и не двигается, пока держится `GlobalLock`.

**Решение.** Хелпер:

```go
func ptr(p uintptr) unsafe.Pointer {
    return *(*unsafe.Pointer)(unsafe.Pointer(&p))
}
```

Он сохраняет биты адреса, не меняет поведение и убирает предупреждение `go vet`.

**Альтернативы.** `reflect.SliceHeader` (устарел, хуже); `ReadProcessMemory` собственной
памяти (лишний syscall); оставить предупреждение и запускать `go vet -unsafeptr=false`
(скрывает и настоящие проблемы).

**Последствия.**
- `GOOS=windows go vet` чистый, CI это проверяет.
- Хелпер нельзя использовать как универсальный обход: он допустим только для валидного
  адреса вне Go-кучи, удерживаемого `GlobalLock`.

## D-016. Релизная политика: Linux stable, Windows alpha, CI

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** Linux проверен вживую, Windows — нет. Нельзя обещать одинаковую зрелость.

**Решение.**
- Linux (GNOME/Wayland, X11) — основная поддерживаемая платформа.
- Windows — alpha, помечено в README, релизах и `diag`.
- CI на GitHub Actions: Linux (build, vet, test, race) и Windows (build, vet, test),
  плюс кросс-сборка `windows/amd64`.
- Релиз — тег `vX.Y.Z` и `janus.exe` в ассетах; заметки честно описывают состояние Windows.

**Альтернативы.** Не выпускать Windows; выпускать без пометки (риск репутации); только
Linux-релизы (теряем обратную связь по Windows).

**Последствия.**
- Windows-пользователь знает, что включает alpha.
- CI ловит регрессии сборки и `vet`, но не заменяет живой прогон.
- Версия и `CHANGELOG` — обязательная часть релиза.

## D-017. Гибкие сочетания: F10 по умолчанию, пунктуация и цифровой блок

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** На 75% клавиатурах нет Pause, Insert, PrintScreen и некоторых других клавиш,
поэтому старые умолчания `Ctrl+Shift+Pause` / `Shift+Pause` делали программу непригодной
сразу после установки. Парсер сочетаний знал только буквы, цифры, F-клавиши и небольшой
набор именованных клавиш; веб-интерфейс не умел поймать пунктуацию и цифровой блок.

**Решение.**
- Умолчания: `Ctrl+Shift+F10` (выделение/слово) и `Ctrl+Shift+F9` (слово). F-ряд есть почти
  на любой 75% клавиатуре и не зависит от раскладки. `Ctrl+Alt+F10` не подошёл: это
  переключение на VT10, `gsd-media-keys` не может его захватить (подтверждено журналом
  2026-11-22).
- `internal/hotkey` принимает пунктуацию (`minus`, `equal`, `bracketleft`, `bracketright`,
  `backslash`, `semicolon`, `apostrophe`, `comma`, `period`, `slash`, `grave`) и цифровой
  блок (`numpad0..9`, `numpadadd`, `numpadsubtract`, `numpadmultiply`, `numpaddivide`,
  `numpaddecimal`, `numpadseparator`, `numpadenter`), плюс CapsLock/ScrollLock/Menu.
- Веб-интерфейс ловит эти клавиши по `event.code` и показывает человекочитаемые подписи.
- Windows переводит те же имена в VK-коды (`internal/winhost/bindings.go`).
- Глобально разрешены только сочетания с модификатором или одиночные F1–F24/Pause/Print
  (`Combo.IsBindable`); одиночная буква или пунктуация перехватила бы ввод.
- В конфиг добавлено `defaults_version`. При загрузке **точные старые умолчания** Pause
  один раз меняются на F10/F9; отдельная миграция версии 3 переводит прежний
  `Ctrl+Alt+F10` на `Ctrl+Shift+F9`. Если пользователь осознанно выбрал сочетание уже с
  текущей версией, миграция его не трогает.

**Альтернативы.** Оставить Pause и просить всех менять вручную (плохой первый запуск);
разрешить только F-клавиши (меньше гибкости); сделать умолчанием букву (зависит от
раскладки на Linux); добавить пресеты без свободного выбора (не покрывает 75% раскладки).

**Последствия.**
- Новые установки работают на 75% клавиатуре без настройки.
- Пользователи со старым умолчанием получат F10/F9 после обновления; это записано в CHANGELOG
  и заметках релиза.
- Пунктуация и цифровой блок требуют модификатора. Живой тест в GNOME показал, что
  `<Control><Shift>j`, `<Control><Shift>backslash` и `<Control><Alt>backslash` срабатывают
  и при активной русской раскладке; F-клавиши остаются запасным вариантом для других систем.
- Добавлены тесты парсера и миграции конфига.

## D-018. Логирование и правдивый health X11/трея

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** После перезагрузки выяснилось, что `janus.log` не содержит времени
открытия/закрытия X11, tray-ошибки не повторяются, а `status` показывает
`clipboard: true` для мёртвого соединения. Для следующего инцидента нужна
диагностика, но журнал не должен превращаться в кейлоггер.

**Решение.**
- `janus.log` с миллисекундами; ротация при 2 МиБ с сохранением `janus.log.1`.
- При старте: версия, pid, uid, Go/OS/arch, boot_id, сессия, аргументы, конфиг,
  хоткеи, источник.
- При остановке: полученный сигнал; heartbeat раз в 10 минут (uptime, RSS, heap,
  goroutines).
- Stdlib-логи (включая `XGB ... EOF`) перенаправляются в тот же журнал.
- `janus logs [N]` — последние строки.
- Текст буфера по умолчанию не пишется: только длина; полный текст — только при
  `JANUS_LOG_TEXT=1`.
- X11: флаг broken, `Ping` реальным запросом, переоткрытие, логи open/close/reopen.
- Трей: item сохраняется при отсутствии watcher, `Watch` всегда запускается,
  регистрация повторяется, status показывает причину.
- `diag` проверяет X11 запросом, а не наличием указателя.

**Альтернативы.** Писать полный текст (риск утечки); не ротировать (потеря лога при
перезапуске); проверять только `c != nil` (ложное «ОК»).

**Последствия.**
- Лог растёт ограниченно; предыдущий файл сохраняется.
- Содержимое буфера не попадает в журнал без явного согласия.
- `XGB`-сообщения получают метку времени.
- Трей может появиться через несколько секунд после логина, без рестарта.

## D-019. uinput: allowlist клавиш и release-all

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** Виртуальная клавиатура объявляла все keybits 0..0x2ff, включая
Delete, Power, Sleep и F-клавиши. Janus их не отправляет, но лишняя возможность
— риск. При ошибке/остановке теоретически могли остаться зажатые модификаторы.

**Решение.**
- `UI_SET_KEYBIT` только для реально нужных клавиш: модификаторы, буквы, цифры,
  пунктуация, Insert/Home/End/стрелки/Space/Tab/Enter/Backspace/Esc.
- Delete, Pause, Print, F-клавиши и power/sleep не объявляются.
- `KeyDown`/`KeyUp` проверяют allowlist.
- `ReleaseAll` отпускает всё, что устройство держит; вызывается при ошибке
  `Chord`/`Tap` и при `Close`.
- Логи создания/удаления устройства.

**Альтернативы.** Оставить все keybits (совместимость, но лишняя поверхность);
отпускать только по SIGTERM (поздно и не покрывает ошибки).

**Последствия.**
- Пользовательские copy/paste-сочетания с Delete/F-клавишами не сработают; UI
  предлагает только поддерживаемые варианты.
- Ctrl+Alt+Del через виртуальную клавиатуру Janus невозможен.
- После ошибки/выхода не остаётся зажатых модификаторов.

## D-020. Инцидент перезагрузки: формулировка и доказательства

**Дата:** 2026-11-22. **Статус:** принято.

**Контекст.** Пользователь сообщил о перезагрузке и предположил вину Janus.
В журнале — `Received SIGINT` → `reboot.target` → `Journal stopped`; panic/OOM/
thermal нет. Последнее действие Janus было за 14 минут до SIGINT, сам он
остановился через 2 секунды после начала reboot.

**Решение.** Публичная формулировка:
> «Зафиксирована упорядоченная перезагрузка, инициированная SIGINT для systemd
> PID 1. Источник сигнала не установлен. Свидетельств причастности Janus в
> представленных данных нет; полностью исключить её по этим данным нельзя.»

Не писать «Janus точно не виноват» и не писать «пользователь нажал
Ctrl+Alt+Del»: отправитель SIGINT не установлен. Отчёт:
`docs/incident-2026-11-22-reboot.md`.

**Альтернативы.** Обвинить Janus (нет доказательств); оправдать полностью (нет
инициатора); откатить продукт (нет признаков аварийного завершения).

**Последствия.**
- Трей и X11 исправлены как отдельные дефекты.
- При повторении инцидента собирать `janus.log`, `janus.log.1`, `journalctl -b -1`
  и `janus diag`.
- Аудит отправителя SIGINT задним числом невозможен без системной трассировки.
